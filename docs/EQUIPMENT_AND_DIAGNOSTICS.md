# Equipment control, permissives and diagnostics

## Common equipment pattern

```text
request -> permission -> command -> feedback supervision -> device status -> fault/alarm
```

The state machine may request an actuator, but the equipment path decides whether that request can become an active command and whether the expected feedback is received.

## Valves

XV101/XV102/XV103 use the reusable `FB_Valve` pattern.

A valve demand is supervised against OpenFb. If the requested state is not proved within the configured supervision time, the valve reports a fault and corresponding diagnostic information to the alarm/sequence path.

For transfer valves, the proved state also participates in the downstream pump permission. This is why XV102 and XV103 are functional interlocks, not just status lamps.

## Pumps

P101/P102 use `FB_Pump` for:

- start demand,
- RunFb supervision,
- overload/trip input,
- running status,
- failed-to-start fault,
- fault code output.

P101 additionally receives the drive-facing status generated by `FC_DriveP101`.

## Permissive separation

`FC_PermissiveLogic` centralizes the conditions that answer *may this requested action run now?* Typical inputs are:

- controller mode / plant state,
- process level conditions,
- associated valve feedback,
- pump overload/trip state,
- plant safety condition,
- active trip/fault state.

This keeps the automatic sequence readable: the sequence describes the process step; the permissive layer describes whether the requested device path is valid.

## First-out diagnosis

When a trip occurs, the resulting safe reaction can change several other conditions immediately. The alarm manager therefore retains the first initiating source.

Examples exercised in the FAT include:

| Initiating source | Retained first-out code |
|---|---:|
| simulated plant safety-chain input | `1001` |
| XV101 feedback fault | `1401` |
| XV102 feedback fault | `1402` |
| XV103 feedback fault | `1403` |
| P101 fault | `1501` |
| P102 fault | `1502` |

The HMI alarm page then gives the operator a direct fault context instead of only showing the consequences of S90.

## Reset and restart

Reset clears the controller's latched fault state according to the implemented reset logic. It does not create an automatic process restart. A new Start is required before the sequence runs again.

A persistent injected field problem can therefore reappear when the affected device is demanded again after restart.

## Manual operation

Manual requests use the same device and permissive paths. They are useful for checking individual equipment behavior, but they do not bypass valve-before-pump or plant safety conditions.
